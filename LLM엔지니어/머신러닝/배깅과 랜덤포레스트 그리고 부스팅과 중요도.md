# TIL | 배깅과 랜덤포레스트, 부스팅과 피처 중요도

**2026-08-12**

앙상블 모델은 크게 **배깅(Bagging)**과 **부스팅(Boosting)**으로 나뉜다. 배깅은 여러 모델을 **병렬로 독립 학습**시켜 **분산(Variance)**을 줄이고, 부스팅은 이전 모델의 실수를 다음 모델이 **순차적으로 보완**하며 **편향(Bias)**을 줄인다.

---

## 1. 배깅과 랜덤포레스트

### 부트스트랩 샘플링 (Bootstrap Sampling)

원본 데이터에서 **중복을 허용해 복원추출**하여, 원본과 **같은 크기**의 샘플을 여러 번 뽑는 방법이다.

* 샘플 크기를 원본보다 작게 하면 정보량이 줄어들기 때문에 항상 원본과 같은 크기로 뽑는다.
* 피처를 무작위로 선택하는 것은 랜덤포레스트의 별도 특징이며, 부트스트랩 자체와는 다르다.
* 즉, 원본과 **크기는 같지만 구성은 조금씩 다른** 여러 데이터셋을 만드는 과정이다.

### 배깅 (Bagging = Bootstrapping + Aggregating)

**분산**은 학습 데이터를 조금만 바꿔도 모델 결과가 크게 달라지는 성질이다. 결정트리 하나만 학습하면 데이터가 조금만 달라져도 정확도가 95% → 82% → 91%처럼 들쭉날쭉해질 수 있다.

배깅은 이 문제를 다음 과정으로 줄인다.

1. 원본 데이터에서 여러 개의 부트스트랩 샘플을 뽑는다.
2. 각 샘플로 여러 개의 나무를 만든다.
3. 마지막에 **평균(회귀)** 또는 **다수결(분류)**로 결합한다.

어떤 나무가 틀린 부분을 다른 나무가 맞추기 때문에, 평균을 내면 결과가 훨씬 안정적이 된다. 한 모델의 실수를 다른 모델들이 보완해주는 셈이다.

> 부트스트랩만 사용하면 강한 피처가 모든 나무의 최상단을 차지해 나무들이 서로 비슷해지는 문제가 생긴다. 피처까지 무작위로 제한하면 나무 사이의 **상관성이 낮아지고 앙상블 효과(분산 감소)가 커진다.** 학습 속도나 OOB 비율, 데이터 크기 축소는 이 무작위성의 목적이 아니다.

**한 줄 정리**
* 부트스트랩 샘플링: 원본 데이터를 복원추출해서 여러 데이터셋을 만드는 것
* 배깅: 그 데이터셋마다 모델을 따로 학습한 뒤 평균/다수결로 합치는 것

### 랜덤포레스트의 두 가지 무작위성

랜덤포레스트는 "서로 조금씩 다른 결정트리를 많이 만들고, 마지막에 다수결이나 평균으로 합치는 방법"이다.

1. **행(row) 무작위 선택**: 데이터가 1,000개라면 나무 A도, 나무 B도 각각 랜덤하게 1,000개를 뽑는다(부트스트랩). 같은 데이터가 뽑힐 수도 있지만 구성은 매번 조금씩 다르다.
2. **피처(feature) 무작위 선택**: 예를 들어 피처가 검색 점수, 문서 길이, 출처, 최신성, 질문 길이 5개라면, 어떤 노드에서는 검색 점수+최신성만, 다른 노드에서는 문서 길이+출처만 후보로 준다. 중요한 점은 이 후보를 **트리 전체에서 한 번 정하는 것이 아니라 각 노드마다 새로 뽑는다**는 것이다.

각 노드는 받은 후보 중에서 데이터를 가장 잘 나누는 피처를 선택한다.

### OOB Score (Out-Of-Bag)

부트스트랩 과정에서 **한 번도 뽑히지 않은 데이터**를 OOB 샘플이라고 한다. 그 나무는 이 행을 학습하지 않았으므로 시험 데이터처럼 사용할 수 있다.

* 모든 나무의 OOB 예측을 모아 계산한 점수가 `oob_score_`이다.
* OOB 비율은 `(1 - 1/n)ⁿ`이 n이 커질수록 `1/e`(약 0.368)에 수렴하기 때문에 항상 약 37% 근처로 나타난다.
* validation을 따로 만들지 않아도 대략적인 성능을 빠르게 확인할 수 있어 유용하다.

> OOB는 빠른 내부 경고등일 뿐이다. 같은 원문의 여러 chunk가 섞이는 문제, 시간에 따른 검색 시스템 변화, 전처리 누수는 자동으로 해결해주지 않는다. **최종 성능 평가는 반드시 validation이나 교차검증으로 해야 한다.**

### 나무를 늘려도 상관이 높으면 분산 감소에 바닥이 생긴다

나무 수(N)를 늘리면 각 나무의 **우연한 오차**는 평균을 내면서 줄어든다. 하지만 나무들이 같은 이유로 함께 틀리면(상관 ρ가 높으면) 그 **공통 오차는 아무리 평균을 내도 사라지지 않는다.**

* 상관이 높다 = 서로 비슷하게 움직인다 = 평균을 내도 오차가 잘 안 없어짐
* 상관이 낮다 = 각자 다른 방식으로 틀림 = 평균을 내면 오차가 서로 상쇄됨

랜덤포레스트가 `max_features`나 부트스트랩을 쓰는 이유도 나무들이 서로 다른 관점에서 학습하도록 만들어 상관을 낮추기 위해서다. 그래서 N이 커질수록 성능 향상은 점점 작아지고 어느 순간 포화된다.

> 학생 100명이 모두 같은 오답을 외웠다면 100명의 답을 평균 내도 그 오답은 그대로다. 반대로 서로 다른 실수를 하면 평균을 낼수록 정답에 가까워진다.

RAG에서도 마찬가지다. 검색기가 항상 같은 문서 3개만 가져온다면, LLM을 여러 개 사용해도 모두 같은 잘못된 문서를 보고 답하기 때문에 평균이나 다수결을 해도 결과는 계속 틀린다. 검색 결과가 다양해야 각 모델이 서로 다른 정보를 보게 되어 같은 실수를 할 가능성이 줄어든다.

## 2. 부스팅 계열 모델의 원리와 발전

### 다음 나무는 무엇을 학습할까?

| | 다음 나무에 전달하는 것 | 핵심 |
|---|---|---|
| **AdaBoost** | 샘플 가중치 | 이전 나무가 틀린 샘플의 가중치를 높여 더 집중해서 학습 |
| **Gradient Boosting** | negative gradient(수정 신호) | 예측을 얼마나, 어느 방향으로 수정할지 학습 |

> "앞 친구가 틀린 만큼만 다음 친구가 조금씩 고쳐 주면서 함께 정답에 가까워지는 방법이야." 여러 사람이 그림을 그릴 때 첫 사람이 대충 그리고, 다음 사람이 부족한 부분만 덧칠하고, 그다음 사람도 남은 부족한 부분만 계속 수정하는 것과 같다.

AdaBoost는 "어떤 데이터를 더 중요하게 볼지"를 바꾸고, Gradient Boosting은 "예측을 얼마나 어떻게 고칠지"를 배운다.

**Weak Learner(약한 학습기)**: 혼자 문제를 해결하지 않고, 이전 모델의 실수를 조금씩 고치는 얕은 결정트리.

**제곱오차(MSE)에서는** `negative gradient = y - F(현재 예측) = 잔차(residual)`이므로 다음 나무는 잔차를 학습한다.

```
실제값:      [80, 40, 60]
현재 예측:    [50, 50, 50]
수정 신호:    [+30, -10, +10]
learning_rate=0.5 적용 → [+15, -5, +5]
새 예측:      [65, 45, 55]
```

이후 라운드에서는 새 예측 `[65, 45, 55]`를 기준으로 다시 수정 신호를 계산해 다음 나무가 학습한다.

> 주의: Gradient Boosting이 항상 잔차(`y - F`)를 학습하는 것은 아니다. 일반적으로는 선택한 손실 함수의 negative gradient를 학습하며, `y - F`는 제곱오차(MSE)에서만 성립하는 특별한 경우다.

### XGBoost · LightGBM · CatBoost 한눈에 정리

공통점: 모두 트리 부스팅(Gradient Boosting) 알고리즘이며, 이전 트리의 실수를 다음 트리가 계속 보완하며 학습한다.

* **XGBoost (Depthwise)**: 루트부터 위쪽을 먼저 확장. 비교적 균형 있게 트리를 키우는 편. 규제(Regularization)와 옵션이 풍부.
* **LightGBM (Leaf-wise)**: 손실을 가장 많이 줄이는 리프 하나를 먼저 확장. 트리가 한쪽으로 깊어질 수 있음. 대용량 데이터에서 매우 빠름.
* **CatBoost (Symmetric)**: 같은 깊이의 모든 리프에 같은 분할 조건을 적용해 항상 대칭적인 트리를 만듦. 범주형(Categorical) 데이터 처리에 강점.

> "세 친구가 나무를 키우는데, 한 명은 위에서부터 키우고(XGBoost), 한 명은 가장 잘 자랄 가지부터 키우고(LightGBM), 한 명은 양쪽을 똑같이 키우는(CatBoost) 차이야." 건물에 비유하면 XGBoost는 층별로 차근차근 올리는 방식, LightGBM은 가장 효과가 큰 방부터 우선 리모델링하는 방식, CatBoost는 좌우를 항상 대칭으로 공사하는 방식이다.

**추가 개념**

* **Histogram**: 연속값을 여러 구간(bin)으로 묶어 계산. 속도와 메모리를 절약하지만 아주 약간의 근사 오차가 생길 수 있다.
* **Ordered Category Statistics**: 범주형 데이터를 숫자로 바꿀 때 현재 행의 정답(자기 자신의 정답)을 사용하지 않아 데이터 누수를 줄이는 기법.
* **Ordered Boosting**: 현재 행의 gradient를 계산할 때 앞부분 데이터로 만든 모델만 사용해 학습. 역시 CatBoost가 데이터 누수를 줄이기 위해 쓰는 기법.

**선택 기준**: XGBoost → 안정적이고 다양한 제약 조건이 필요할 때 / LightGBM → 데이터가 매우 크고 학습 속도가 중요할 때 / CatBoost → 원본 범주형 컬럼이 많을 때.

> 이 차이는 누가 더 좋은지 순위가 아니라 **트리를 키우는 방식의 차이**다. 실제 성능은 같은 데이터와 같은 평가 조건에서 직접 비교해야 한다.

### 학습률 · 반복 수 · Early Stopping

* **learning_rate**: 새 나무의 예측을 얼마나 조금씩 반영할지(보폭) 결정. 예) 나무가 +20을 제안할 때 `lr=0.1` → +2만 반영, `lr=0.05` → +1만 반영.
* **n_estimators(또는 max_iter)**: 최대 몇 번까지 나무를 추가할지 결정. 학습률이 작으면 보통 더 많은 반복이 필요하지만, 학습률을 절반으로 줄였다고 반복 수가 정확히 2배가 되거나 성능이 항상 좋아지는 것은 아니다.

함께 조절하는 주요 하이퍼파라미터

* `learning_rate × iterations` → 한 번에 얼마나 움직이고, 몇 번 수정할지
* 리프 수 · 깊이 · L2 → 나무 하나가 얼마나 복잡하게 수정할지
* `subsample` → 매 반복마다 어떤 학습 데이터를 사용할지

**Early Stopping**: 최대 반복 수는 크게 설정하고, validation 성능이 일정 횟수(patience) 동안 좋아지지 않으면 학습을 종료한다.

```
Loss: 0.42 → 0.36 → 0.33 → 0.31 → 0.315 → 0.319 → 0.325
Best iteration = 4 (가장 성능이 좋았던 시점)
Stop iteration = 7 (3번 더 기다린 후 종료)
```

### 부스팅은 왜 편향을 줄일 수 있을까?

**편향(Bias)**은 모델이 너무 단순해서 중요한 패턴을 계속 놓치는 현상이다. 부스팅은 이전 나무가 틀린 부분을 다음 나무가 계속 보완하는 방식이다.

첫 번째 나무는 큰 규칙만 배우고, 다음 나무들이 놓친 세부 패턴을 하나씩 학습한다. 이렇게 여러 나무의 수정이 누적되면 모델의 표현력이 커져 편향이 감소하는 경향이 있다. 다만 나무를 너무 많이 추가하면 우연한 데이터나 노이즈까지 외워 과적합될 수 있으므로, validation 성능을 보며 **Early Stopping**으로 적절한 시점에 멈추는 것이 중요하다.

### Validation 결과 해석

* Train ↓ / Validation ↓ → **과소적합**, 중요한 특성 부족, 라벨 문제
* Train ↑ / Validation ↓ → **과적합**, 데이터 누수, 규제 부족
* 무작위 분할은 좋지만 미래 데이터는 나쁨 → **데이터 분포나 서비스 환경 변화**

"연습문제에서는 잘 맞았는데 실전에서는 못 맞춘다"는 데이터의 특성(분포)이나 서비스 환경이 시간이 지나며 바뀌었다는 신호다. 대표적인 원인: 검색 알고리즘 변경, 사용자 행동 변화, 새로운 문서 종류 증가, 서비스 정책 변경, 계절성. 작년 기출문제로는 100점을 받았지만 올해 출제 경향이 바뀌면 실전 점수가 떨어지는 것과 같다.

**꼭 기억할 점**: 배깅 = 분산 감소 경향 / 부스팅 = 편향 감소 경향. 단, 절대 법칙은 아니며 설정과 데이터에 따라 둘 다 편향과 분산에 영향을 줄 수 있다.

> 심화(통계적 Bias): 여러 번 다른 데이터로 학습했을 때 평균적으로 실제 정답에서 얼마나 벗어나는지를 의미한다. 한 번의 예측 오차가 아니라 **평균적인 오차의 방향**을 말한다.

## 3. 모델 선택과 SHAP

### 배깅 vs 부스팅

부스팅은 이전 나무가 틀린 부분만 이어서 고치는 방식이라 **현재 앙상블을 다음 나무가 보완**한다. 반대로 배깅(랜덤포레스트)은 각자 독립적으로 예측하고 마지막에 평균만 낸다 — 나무2는 나무1이 무엇을 예측했는지 전혀 모른다.

* 배깅: 여러 나무가 각자 따로 예측하고 마지막에 평균낸다.
* 부스팅: 여러 나무가 앞선 나무의 부족한 부분을 차례대로 고치며 예측을 만든다.

### 피처 중요도 3가지: MDI, Permutation, SHAP

**MDI (Mean Decrease Impurity)**
"학습할 때 이 피처를 얼마나 많이 활용했나?" 트리가 분할할 때 불순도를 많이 줄인 피처일수록 중요도가 높다. 학습 과정만 보고 계산하므로 매우 빠르다. 단점: 고유값이 많은 피처(request_id 등)를 중요하게 착각할 수 있다.

**Validation Permutation Importance**
"이 피처를 망가뜨리면 성능이 얼마나 떨어질까?" 학습된 모델은 그대로 두고 validation에서 해당 피처만 무작위로 섞는다. AP가 많이 떨어질수록 그 피처에 많이 의존한 것이다 (예: AP `0.420 → 0.317`이면 중요도는 0.103). 음수라면 섞었더니 성능이 오히려 조금 좋아졌다는 뜻이다.

**SHAP (SHapley Additive exPlanations)**
게임이론의 섀플리 값을 활용해 각 피처가 예측값을 기준값에서 얼마나, 어느 방향으로 이동시켰는지를 계산하는 해석 기법이다. 기존 feature importance와 달리 **부호가 있는 기여도**로 개별(지역) 예측까지 설명할 수 있다. "이 예측 결과를 만든 공은 누구에게 얼마나 있을까?"를 묻는다. 양수는 예측값을 높인 기여, 음수는 예측값을 낮춘 기여이며, 모델이 왜 이런 예측을 했는지 설명할 때 가장 많이 사용한다.

**한 줄 비교**
* MDI → 학습할 때 많이 사용된 피처는?
* Permutation → 없어지면 성능이 가장 떨어지는 피처는?
* SHAP → 이번 예측에 가장 큰 영향을 준 피처는?

**왜 결과가 다를까?** 세 방법이 서로 다른 질문을 하기 때문이다. 비슷한 역할을 하는 피처가 둘 있으면 MDI는 한쪽에 점수가 몰릴 수 있고, Permutation은 하나를 섞어도 다른 하나가 대신해 성능이 크게 안 떨어질 수 있으며, SHAP은 둘이 기여를 나눠 가질 수도 있다.

> 축구에 비유하면 MDI는 공을 가장 많이 만진 선수를 찾는 것, Permutation은 그 선수를 빼고 경기했을 때 팀 성적이 얼마나 나빠지는지 보는 것, SHAP은 이번 골이 들어갈 때 각 선수가 얼마나 기여했는지 나누는 것이다.

> "중요한 친구를 찾는 방법도 '열심히 일한 친구', '없으면 제일 힘든 친구', '이번 성공에 가장 많이 도와준 친구'처럼 기준이 서로 다르다."

또한 MDI는 훈련에서 많이 사용한 선수, Permutation Importance는 실제 경기에서 빠졌을 때 팀이 얼마나 약해지는 선수를 보는 차이로 이해할 수 있다. 축구 감독이 선수를 자주 선발 명단에 넣었다고 해서 실제 경기에서 가장 큰 활약을 했다는 뜻은 아니다. **MDI는 높은데 Permutation은 거의 0이라면?** 학습할 때는 많이 썼지만 실제 예측에는 없어도 성능이 거의 안 떨어진다는 뜻이며, 보통 데이터 누수, 높은 cardinality, 상관된 다른 피처를 의심한다.

## 오늘의 핵심 정리

* **부트스트랩**: 원본을 복원추출해 같은 크기의 데이터셋을 여러 개 만드는 것
* **배깅**: 데이터셋마다 모델을 따로 학습해 평균/다수결로 합침 → **분산 감소**
* **랜덤포레스트**: 배깅 + 노드마다 피처를 무작위로 제한 → 나무 간 상관 감소 → 앙상블 효과 강화
* **OOB Score**: 부트스트랩에서 빠진 ~37% 데이터로 빠르게 확인하는 내부 검증 점수 (최종 평가는 아님)
* **나무 상관관계**: 나무 수를 늘려도 상관이 높으면 분산 감소에 한계가 생김
* **AdaBoost**: 샘플 가중치 조정 / **Gradient Boosting**: negative gradient(수정 신호) 학습 → **편향 감소**
* **XGBoost/LightGBM/CatBoost**: 트리를 키우는 방식(Depthwise/Leaf-wise/Symmetric)의 차이일 뿐, 절대적 우열은 없음
* **learning_rate & n_estimators & Early Stopping**: 보폭과 반복 횟수를 함께 조절하며 과적합 직전에 멈춤
* **MDI vs Permutation vs SHAP**: "많이 썼나?" vs "없으면 성능이 떨어지나?" vs "이번 예측에 얼마나 기여했나?" — 질문이 다르므로 결과도 다를 수 있음

결국 배깅은 서로 다른 관점을 가진 모델들을 **병렬로 합쳐 흔들림(분산)을 줄이는 전략**이고, 부스팅은 부족한 부분을 **순차적으로 채워가며 놓친 패턴(편향)을 줄이는 전략**이다.
