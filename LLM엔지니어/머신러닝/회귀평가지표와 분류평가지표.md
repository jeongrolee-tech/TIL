## 1. 문제 유형과 데이터 분리

머신러닝의 문제는 크게 **지도학습**과 **비지도학습**으로 나눌 수 있다.

지도학습은 정답(Label)이 있는 데이터를 이용해 학습하며, 대표적으로 **회귀(Regression)**와 **분류(Classification)**가 있다. 회귀는 연속적인 숫자를 예측하는 문제이고, 분류는 데이터를 특정 범주로 나누는 문제이다.

비지도학습은 정답 Label 없이 데이터 자체의 구조를 찾는 방식이며, 대표적으로 **군집화(Clustering)**와 **차원축소(Dimensionality Reduction)**가 있다.

데이터를 모델 학습에 사용할 때는 일반적으로 **Train / Validation / Test**로 분리한다.

* **Train**: 모델이 실제로 학습하는 데이터
* **Validation**: 하이퍼파라미터 튜닝과 모델 선택에 사용하는 데이터
* **Test**: 최종적으로 일반화 성능을 평가하는 데이터

Validation에서는 여러 하이퍼파라미터나 모델을 비교하고, 그중 가장 좋은 설정을 선택한다. 이후 최종적으로 선택된 모델을 Test 데이터에 적용해 실제 성능을 확인한다.

분류 문제에서는 데이터 분할 시 **`stratify`** 옵션을 사용할 수 있다. `stratify`는 Train과 Validation 등에 **클래스 비율이 최대한 유지되도록 데이터를 분할**하는 설정이다.

### 데이터가 적을 때: Cross-Validation

데이터가 적으면 Validation 데이터를 별도로 떼어놓는 것 자체가 학습 데이터의 감소로 이어질 수 있다. 이때 **K-Fold Cross-Validation**을 사용하면 데이터를 여러 번 나누어 번갈아 Validation에 사용함으로써 적은 데이터에서도 보다 안정적인 성능 추정을 할 수 있다.

## 2. 회귀 평가지표

회귀는 연속적인 숫자를 예측하기 때문에 **예측값과 실제값의 차이인 오차**를 기준으로 모델의 성능을 평가한다. 일반적으로 오차가 작을수록 좋은 모델이다.

### MSE (Mean Squared Error)

실제값과 예측값의 차이를 제곱한 뒤 평균을 구한다.

**특징:** 큰 오차에 더 큰 벌점을 주며, 단위가 제곱된다.

따라서 큰 실수를 중요하게 보는 상황에서 유용하지만, 이상치의 영향을 크게 받을 수 있다.

### RMSE (Root Mean Squared Error)

MSE에 제곱근을 적용한 지표이다.

**특징:** MSE처럼 큰 오차에 큰 벌점을 주면서도 **원래 데이터와 동일한 단위로 해석할 수 있다.**

예를 들어 배달 시간을 예측한다면 RMSE도 `분` 단위로 해석할 수 있기 때문에 직관적이다.

### MAE (Mean Absolute Error)

실제값과 예측값의 차이의 절댓값을 평균낸 값이다.

**특징:** MSE나 RMSE에 비해 이상치의 영향을 상대적으로 덜 받으며, 평균적으로 얼마나 틀리는지 직관적으로 확인할 수 있다.

### R² (R-squared)

모델이 데이터의 변동성을 얼마나 설명하는지를 나타내는 지표이다.

**1에 가까울수록 좋으며, 0은 평가 데이터의 평균값을 예측하는 기준 모델과 비슷한 수준의 설명력을 의미한다.**

RMSE와 MAE를 함께 보면 모델의 평균적인 오차뿐만 아니라 **큰 실수가 발생하고 있는지**도 파악할 수 있다.

예를 들어 폭설로 인해 배달 시간이 유난히 길어진 날처럼 **큰 오차를 놓치면 안 되는 서비스라면 RMSE**, 대부분의 평범한 상황에서 발생하는 일반적인 오차를 중심으로 평가하고 싶다면 **MAE**가 더 적합할 수 있다.

## 3. 분류 평가지표

분류 문제에서는 **Accuracy만으로 모델을 평가하면 위험할 수 있다.**

특히 클래스가 한쪽으로 치우친 **불균형 데이터**에서는 정확도가 높더라도 실제로 중요한 양성 데이터를 거의 찾아내지 못하는 상황이 발생할 수 있다.

따라서 문제의 비용 구조에 따라 **Precision, Recall, F1, ROC-AUC, AP** 등의 지표를 적절하게 선택해야 한다.

### Accuracy

전체 데이터 중에서 모델이 정확하게 예측한 비율이다.

직관적이지만 불균형 데이터에서는 주의해서 사용해야 한다.

### Precision

모델이 **양성이라고 예측한 데이터 중 실제 양성인 비율**이다.

즉, 양성이라고 판단했을 때 얼마나 믿을 만한지를 나타낸다.

**오탐(False Positive)의 비용이 큰 경우 중요하다.**

### Recall

실제 **양성 데이터 중 모델이 양성으로 찾아낸 비율**이다.

즉, 실제 양성을 얼마나 놓치지 않고 찾아냈는지를 나타낸다.

**놓침(False Negative)의 비용이 큰 경우 중요하다.**

### F1 Score

Precision과 Recall의 **조화평균**이다.

Precision과 Recall 중 한쪽만 높아지는 것을 방지하면서 두 지표의 균형을 확인할 수 있다.

### ROC-AUC

특정 임계값 하나에 고정하지 않고, 다양한 임계값에서 **양성 데이터를 음성 데이터보다 높은 점수로 순위화하는 능력**을 평가한다.

### AP (Average Precision)

Recall이 증가하는 과정에서 Precision을 종합적으로 평가하는 지표이다.

특히 **양성이 희소한 불균형 데이터에서 양성 데이터를 얼마나 높은 순위에 잘 배치하는지**가 중요할 때 유용하다.

---

## 4. Precision과 Recall을 함께 보는 이유

Precision과 Recall은 일반적으로 **Trade-off 관계**를 가진다.

양성이라고 판단하는 기준을 엄격하게 만들면 잘못된 양성 예측이 줄어들어 Precision은 높아질 수 있지만, 실제 양성까지 놓칠 가능성이 커져 Recall은 낮아질 수 있다.

반대로 기준을 느슨하게 하면 더 많은 양성을 찾아 Recall은 높아질 수 있지만, 실제로는 음성인 데이터를 양성으로 판단하는 경우가 증가하여 Precision이 낮아질 수 있다.

따라서 어느 한쪽만 보는 것이 아니라 **문제의 비용 구조에 따라 Precision과 Recall의 중요도를 결정**해야 한다.

두 지표의 균형을 하나의 값으로 확인하고 싶다면 **F1 Score**를 사용할 수 있다.

# 5. 핵심 머신러닝 모델

## Linear Regression / Logistic Regression

선형모델은 각 특성에 가중치를 곱한 뒤 더하는 **가중합**을 기반으로 예측한다.

`예측값 = w₁x₁ + w₂x₂ + ... + wₙxₙ + b` // 각 특성의 가중합에 절편을 더해 예측

여기서 `w`는 각 특성의 가중치이고 `b`는 절편이다.

**Linear Regression**은 연속적인 값을 예측하는 회귀 문제에 사용하고, **Logistic Regression**은 0~1 사이의 확률을 계산하여 분류 문제에 사용한다.

선형모델은 구조가 단순하고 해석하기 쉬운 편이기 때문에 **분류나 회귀 문제의 Baseline 모델**로 사용하기 좋다.

---

## KNN (K-Nearest Neighbors)

KNN은 **거리 기반 모델**이다.

새로운 데이터가 들어오면 해당 데이터와 가장 가까운 **K개의 이웃**을 찾고, 이들의 정답을 참고하여 예측한다.

분류에서는 가까운 이웃의 **다수결**, 회귀에서는 가까운 이웃의 **평균값**을 이용한다.

KNN은 별도의 복잡한 학습 과정이 거의 없고 직관적이지만, 거리 계산을 사용하기 때문에 **특성의 스케일에 매우 민감하다.**

예를 들어 `나이`와 `연봉`을 그대로 거리 계산에 사용하면 값의 범위가 큰 연봉이 거리에 훨씬 큰 영향을 줄 수 있다. 따라서 KNN에서는 일반적으로 **스케일링이 중요하다.**

K의 값은 Validation 또는 Cross-Validation을 통해 여러 값을 비교하여 적절한 값을 선택할 수 있다. 분류에서는 홀수 K를 사용하면 동점 발생을 줄이는 데 도움이 된다.

---

## Decision Tree

Decision Tree는 데이터를 가장 잘 구분할 수 있는 **질문을 반복해서 데이터를 분할하는 규칙 기반 모델**이다.

예를 들어 다음과 같은 형태로 데이터를 나눌 수 있다.

`나이가 30 이상인가? → YES → 소득이 5천만 원 이상인가?` // 조건에 따라 데이터를 분할

사람이 이해하기 쉬운 규칙 형태로 표현할 수 있고 **스케일링이 필요하지 않으며 비선형 관계도 학습할 수 있다.**

하지만 트리의 깊이가 지나치게 깊어지면 학습 데이터를 과도하게 외워 **과적합(Overfitting)**이 발생할 수 있다.

이를 방지하기 위해 `max_depth`로 트리의 최대 깊이를 제한하거나, 잎 노드에 필요한 최소 샘플 수 등을 제한할 수 있다.

또한 하나의 트리만 사용하는 대신 여러 개의 트리를 결합하는 **앙상블(Ensemble)** 방식으로 확장할 수 있으며, 대표적으로 **Random Forest와 Boosting**이 있다.

# 6. 비지도학습: K-means와 PCA

## K-means

K-means는 **정답 Label이 없는 비지도학습 기반의 군집화 알고리즘**이다.

데이터를 미리 정한 `K`개의 그룹으로 나누고, 각 그룹의 중심(Centroid)을 기준으로 가장 가까운 그룹에 데이터를 배정하는 과정을 반복한다.

즉, 핵심은 **"비슷한 데이터끼리 K개의 그룹으로 묶는다."**

대표적인 활용 사례로는 고객 세분화, 사용자 행동 패턴 분석, 이미지 색상 압축 등이 있다.

---

## PCA (Principal Component Analysis)

PCA는 **차원축소**를 위한 대표적인 비지도학습 기법이다.

많은 특성을 가진 데이터를 정보 손실을 최소화하면서 더 적은 수의 차원으로 압축한다.

PCA는 데이터의 **분산을 최대한 보존하는 방향**을 새로운 축으로 선택한다.

따라서 특성이 수십~수백 개처럼 많은 데이터에서 차원을 줄이거나, 시각화·노이즈 제거·전처리 등의 목적으로 활용할 수 있다.

### 변동성

**변동성 = 데이터 값들이 평균 주변에서 얼마나 퍼져 있는가**

PCA를 이해할 때 중요한 개념으로, 데이터가 어느 방향으로 가장 크게 퍼져 있는지를 기준으로 중요한 축을 찾는다.

# 7. 모델 선택 기준

실무에서는 처음부터 가장 복잡한 모델을 선택하기보다 **단순하고 해석하기 쉬운 모델을 Baseline으로 설정한 뒤 필요한 만큼 복잡한 모델로 확장하는 방식**이 좋다.

모델을 선택할 때는 다음과 같은 요소를 고려한다.

* 데이터의 크기
* 특성의 스케일
* 데이터의 비선형성
* 모델의 해석 가능성
* 과적합 가능성
* 문제에 적합한 평가지표

예를 들어 선형모델에서 성능을 개선하고 싶다면 **Ridge / Lasso**와 같은 규제 모델로 확장할 수 있고, Decision Tree에서 더 높은 일반화 성능이 필요하다면 **Random Forest / Boosting**과 같은 앙상블 모델을 고려할 수 있다.

하이퍼파라미터 튜닝은 여러 후보 설정을 동일한 Cross-Validation 방식으로 비교하여 **일반화 성능이 더 좋은 설정을 선택하는 과정**이다. 단, 하이퍼파라미터 튜닝을 한다고 해서 항상 기본값보다 성능이 좋아진다는 보장은 없다.

# 8. 오늘의 핵심 정리

**문제 유형 → 데이터 분리 → 평가지표 → Baseline 모델 → 모델 선택 → 튜닝 및 확장**의 흐름으로 이해하면 된다.

* **회귀** → 연속적인 숫자 예측
* **분류** → 범주 예측
* **군집화** → 비슷한 데이터끼리 그룹화
* **차원축소** → 정보를 최대한 보존하면서 특성 압축
* **Train** → 학습
* **Validation** → 모델/하이퍼파라미터 선택
* **Test** → 최종 일반화 성능 평가
* **데이터가 적음** → Cross-Validation
* **KNN** → 거리 기반 → 스케일링 중요
* **Decision Tree** → 규칙 기반 → 스케일링 불필요
* **K-means** → 군집화
* **PCA** → 차원축소
* **Linear/Logistic Regression** → 선형모델 → Baseline에 적합
* **Precision** → 오탐이 중요할 때
* **Recall** → 놓침이 중요할 때
* **F1** → Precision과 Recall의 균형
* **ROC-AUC / AP** → 순위 기반 평가
* **Ridge / Lasso** → 선형모델의 규제
* **Random Forest / Boosting** → 트리 기반 앙상블

결국 이번 장에서 가장 중요한 것은 **"좋은 모델을 고르는 것보다 먼저, 어떤 문제인지 정의하고 그 문제에 맞는 평가 기준을 정하는 것이 중요하다"**는 점이다.

**이 문제를 초등학생에게 한 문장으로 설명하면 뭐라고 말할까?** → **"머신러닝은 문제에 맞는 방법으로 데이터를 공부하고, 처음 보는 문제를 얼마나 잘 맞히는지 시험하는 과정이다."**
