- 기업이 자체 LLM 을 갖고 싶어 하는 이유
    - 규제와 보안
    - 비용
    - 데이터 주권
    - 수요: 금융, 공공, 의료 및 제약, 제조, 방산 및 통신 등
- 사용방식 => 요즘은 하이브리드로 섞어 쓴다
    - 외부 api
    - 클라우드 gpu
    - 온프레미스
- 주요업무
    - 어떤 모델을 쓸지(오픈소스/상용api/섞을지)
    - 처리량과 응답지연 잡기(vLLM)
    - 사내 문서 RAG 적용
    - 답변을 검증하는 자동으로 채점하는 평가 체계를 만듦
    - 자원,비용,장애 모니터링, 안전하게 모델 교체
- 레이어
    - 하드웨어(GPU, 전력 및 냉각, 네트워크)
    - 플랫폼(쿠버네티스, GPU 스케줄링, 컨테이너 레지스트리)
    - 모델(오픈소스 가중치 반입/양자화/서빙 엔진 적재, 또는 상용 api 게이트웨이)
    - 애플리케이션(RAG, 벡터DB, ..)
    - 운영(평가/모니터링/로깅/비용 관리)
- 업무 사이클 예시
    - 사내 문서 검색 AI를 온프레미스에 올리기
        - 요건 정의
        - 모델 선정/반입
        - RAG 구축
        - 서빙/최적화
        - 평가/운영
- 스택
    - 모델 => 가장 좋은 모델이 아니라 우리 GPU에 들어가면서 쓸 만한 모델
        - 라이선스
        - 크키/VRAM
        - 한국어 성능
    - 양자화 => 왜 하고 무엇을 잃나
        - 모델을 GPU에 밀어 넣는 기술
        - 14GB(7B 모델도 GPU 가 버겁다) -> 4GB(노트북에서도 돌아간다)
    - 서빙 => vLLM이 빠른 이유
        - 페이징
            - PagedAttention - GPU 메모리를 페이지 단위로 쪼개 쓴다. 동적으로 낭비를 줄여 더 많이 태운다.
        - 연속 배치
            - 요청을 모아 기다리지 않고, 끝난 자리에 새 요청을 바로 밀어 넣는다
        - 캐시 재사용
            - prefix caching - 같은 앞부분(시스템 프롬프트 등)은 다시 계산하지 않는다
            - 같은 질문은 재계산 하지 않도록
    - RAG => 우리 문서로 답하게 만들기
        - 문서 수집 - 어떤 문서를 어떤 권한으로
        - 청킹 - 문서를 어떤 크기로 자를지. 크면 잡음, 작으면 맥락 소실
        - 임베딩/색인 - 벡터로 바꿔 DB에 넣는다. 한국어 임베딩 모델 선택이 관건
        - 검색/리랭킹 - 후보를 넉넉히 뽑고 리랭커로 재정렬. 정확도 상승
        - 생성/인용 - 찾은 근거만 보고 답하게 하고, 출처를 같이 보여준다
    - 오케스트레이션 => GPU를 팀끼리 나누고 모델 서버의 생애주기를 표준화하기
        - 쿠버네티스 위에서
            - 보통 파드 1개가 GPU를 통째로 점유한다(잘게 쓰는 그림이 아님)
            - 누가 얼마나 쓸지 큐와 우선순위를 정한다
            - 모델 서버를 자동으로 띄우고, 교체하고, 되돌린다(오퍼레이터, CI/CD)
            - 폐쇄망이면 컨테이너 레지스트리/패키지 미러를 내부에 직접 세운다
            - 장애 시 어느 층이 문제인지 가른다 - GPU? 드라이버? 서빙 엔진? 애플리케이션?
    - 평가/관측 => 잘 돌아가는지 어떻게 아나
        - 평가 - 품질을 숫자로
            - LLM-as-judge 다른 모델로 답변을 자동 채점한다
        - 관측 - 무슨 일이 있었나
            - 요청/응답/지연/토큰을 추적한다(트레이싱)
            - 대시보드 만드는 일
        - 얼마나 쓰고 있나
            - GPU 시간과 토큰을 대시보드로 본다. 비용이 곧 성과 지표
    - 배포 => 모델도 롤링/카나리로 바꾼다
        - 카나리 - 가장 많이 씀
            - 새 모델에 트래픽 5%만 흘리고 품질 지표를 지켜본 뒤 늘린다
        - 섀도
            - 트래픽을 복제해 새 모델에도 보내되 응답은 버린다. 순수 평가용
        - 롤백
            - 이상하면 즉시 이전 버전으로. 모델 버저닝과 레지스트리가 전제
        - 제약
            - GPU가 1장 뿐이면 무중단 배포가 불가능 합니다(구/신 모델을 동시에 못 띄웁니다)
- 어떤 역량이 필요한가
    - 기초 역량
    - 핵심 기술
    - 실무 도구
- 회사 유형에 따라 하는 일이 다르다
    - 대기업 인하우스 - 그룹 표준 ai 플랫폼 구축/운영. 규제 대응 비중 큼
    - SI/MSP - 여러 고객사에 반복 구축. 경험이 빨리 쌓이고 폭이 넓음
    - AI 솔루션 기업 - 제품으 ㅣ서빙/최적화 담당. 기술 깊이가 요구됨
    - 스타트업 - 인프라부터 앱까지 다 함. 성장은 빠르지만 정신 없음
- 이런 성향이 잘 맞다
    - 트러블슈팅. 서비스가 죽었을 때 원인을 끝까지 파고드는 게 성미에 맞는 사람
    - 새 기술보다 '안정적으로 돌아가는 것'에서 만족을 느끼는 사람
    - 문서/로그/설정을 읽는 걸 귀찮아하지 않는 사람
    - 느린 걸 빠르게, 비싼 걸 싸게 만드는 최적화에서 재미를 느끼는 타입
